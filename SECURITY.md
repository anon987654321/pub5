# Security policy

## Supported source

The current default branch is the primary maintained source. No multi-version
security-support schedule is published; do not assume an older commit or
release receives security fixes unless its release notes say so.

## Report a vulnerability privately

Do not open a public issue, discussion or pull request containing an
unfixed vulnerability or an exploit.

Use GitHub's **Report a vulnerability** control in the repository's Security
tab when private vulnerability reporting is enabled. Availability is controlled
by repository settings. If that private-reporting control is unavailable,
contact the repository owner through their GitHub profile and agree on a
private channel before sending technical details.

A useful report includes the affected commit or path, the impact, a minimal
reproduction using disposable data, and any relevant platform/runtime
conditions. Redact credentials, tokens, private keys, personal data, production
database rows, customer addresses and unredacted operational logs.

## Response expectations

No response-time or service-level commitment is published. A report is
reviewed as maintainer capacity allows. Do not assume that receipt of a report
means a fix or release has been approved.
